# 農工大弓道部アプリ（外枠 / ホーム画面アプリ）

このフォルダは GitHub Pages で公開する「外枠」です。
Googleログインとホーム画面アプリ（PWA）を担当し、アプリ本体（Google Apps Script）を中に表示します。

```
部員のスマホ ─ 外枠（GitHub Pages） ─ アプリ本体（GAS・新オーナー所有） ─ スプレッドシート（新オーナー所有）
                 └ Googleログイン → アプリ本体が「合言葉」を発行（30日・使うたびに延長）
```

設定するのは `index.html` の `CONFIG.APP_URL` だけです。

---

## 引っ越しの手順

作業はすべて **新オーナーのGmail** で行います（「旧」と書いた所だけ大学アカウント）。
1〜5 は部員に影響しません。6 で切り替えます。

### 1. Google Cloud（ログインの設定）

1. Google Cloud のプロジェクトが **新オーナーのGmail所有** か確認する。
   大学アカウントで作ったプロジェクトなら、卒業で消えるので新オーナーで作り直し、
   発行された クライアントID を `コード.gs` の `GOOGLE_CLIENT_ID` と `index.html` の `CLIENT_ID` に入れる。
2. OAuth同意画面：ユーザーの種類は「外部」。
   - テスト中は「テストユーザー」に、試す人のアドレスを追加する（大学アカウントも追加）。
   - 全員に配る前に「アプリを公開」で本番にする。使うのはメールアドレスとプロフィールだけなので、審査は不要の範囲。
     **テストのままだと、テストユーザー以外はログインできない。**
3. 認証情報 → OAuthクライアントID（ウェブアプリケーション）→「承認済みの JavaScript 生成元」に
   `https://GitHubのユーザー名.github.io` を追加（末尾の / やフォルダ名は付けない）。リダイレクトURIは不要。

### 2. GitHub Pages（外枠を公開）

1. 新オーナーのGmailで GitHub アカウントを作る。
2. 公開リポジトリ `kyudo-app` を作り、このフォルダの中身（index.html, manifest.webmanifest, sw.js, icons/, README.md）をアップロード。
3. Settings → Pages → Branch を `main` / `(root)` にして Save。
   数分で `https://ユーザー名.github.io/kyudo-app/` が開けるようになる。

### 3. アプリ本体（GAS）

1. 新しいスプレッドシートを作る（空でよい）。URLの `/d/` と `/edit` の間がID。
2. 新しい Apps Script プロジェクトを作り、3つのファイルを貼る。
   ファイル名は `コード.gs`・`index`（HTML）・`js`（HTML）にする（名前が違うと読み込めない）。
3. `コード.gs` の `SHEET_ID` を 1 のIDに書き換える。
4. プロジェクトの設定 → スクリプト プロパティ：

   | 名前 | 値 |
   |---|---|
   | `SHELL_ORIGIN` | `https://ユーザー名.github.io` |
   | `SHELL_URL` | `https://ユーザー名.github.io/kyudo-app/` |
   | `EXTRA_ALLOWED_EMAILS` | 大学アカウント以外で入れる人（開発者・テスト用のGmail。カンマ区切り） |
   | `LINE_TOKEN` | 旧アプリと同じ値 |
   | `ANTHROPIC_KEY` | 使う時だけ |

   `SESSION_SECRET` は自動で作られる（消すと全員ログインし直し）。
5. デプロイ → 新しいデプロイ → ウェブアプリ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（本人確認はアプリ側の合言葉で行う）
6. 発行されたURL（`https://script.google.com/macros/s/.../exec`）を、外枠の `index.html` の `APP_URL` に入れて GitHub に上げ直す。
7. エディタで `setupBackupTrigger` と `setupShiftReminderTrigger` を1回ずつ実行（権限の許可を求められたら許可）。

### 4. 外部のものの共有を確認

- **シフト表のスプレッドシート**：新オーナーのGmailで開けるように共有する（大学内限定だと読めない）。
- **LINE連携のWebhook**：連携コードを受け取る別のGASがある場合、それも新オーナーに移し、
  `SHEET_ID` を新しいスプレッドシートにして、LINE Developers の Webhook URL を新しいものに変える。

### 5. テスト（部員には影響なし）

1. スマホで `https://ユーザー名.github.io/kyudo-app/` を開き、テストユーザーの大学アカウントでログイン。
2. 新しいスプレッドシートは空なので、最初は新規登録の画面になる。動作確認だけして、データは 6 で入れる。
3. ホーム画面に追加して、アプリとして開けるか確認。

### 6. 切り替え日

1. 部員に「○時から○分ほど使えません」と連絡。
2. **旧アプリ**（大学アカウント）のコード.gs に、今回のコード.gs の末尾にある
   `exportForMigration` を貼り、doGet の中身を次の1行にしてデプロイを更新（旧アプリに書き込まれないようにする）：
   ```js
   return HtmlService.createHtmlOutput('<p style="font-family:sans-serif;padding:2rem">弓道部アプリは引っ越しました。<a href="https://ユーザー名.github.io/kyudo-app/" target="_top">新しいアプリを開く</a></p>');
   ```
3. 旧アプリで `exportForMigration` を実行 → ドライブにできた `kyudo_export_日時.json` をダウンロード。
4. 新オーナーのドライブにアップロード。ファイルのURLの `/d/` と `/view` の間がファイルID。
5. 新アプリの `importFromDriveRun` の中にファイルIDを書いて実行 → 実行ログで件数を確認。
6. OAuth同意画面を「本番」にする（まだなら）。
7. 部員に新しいURLを連絡。初回だけ大学アカウントでログイン、その後はホーム画面から開くだけ。

うまくいかない時は、旧アプリの doGet を元に戻せばすぐ元通り（旧データはそのまま残っている）。

---

## 注意

- **メール**：Gmail所有のGASは1日100通まで（大学アカウントは1,500通）。シフト前の連絡が多い日は足りなくなる可能性がある。
- **自動実行**：Gmail所有だとトリガーの実行時間が1日合計90分まで。シフト確認（10分ごと）は通常この範囲に収まる。
- **画面上部の帯**：Gmail所有のGASは「Googleではなく、別のユーザーが作成したアプリ」という帯が出る（Googleの仕様で消せない）。
- **外枠を更新した時**は `sw.js` の `CACHE` の番号を1つ上げる（上げないと古い外枠が残る）。アプリ本体の更新はGASのデプロイだけでよい。
